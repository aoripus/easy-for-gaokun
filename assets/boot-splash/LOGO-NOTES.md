# 开机画面 LOGO 资源说明（easy-for-gaokun 自有标识）

> 交付目录：`%TEMP%\splash\`　生成日期：2026-09-15
> 用途：Plymouth 启动画面**屏幕正中央**的标识，深色背景（`#1A1A1A` / `#000`），带 alpha 透明通道。
> 本文件与 `logo.svg` / `make-logo.py` 是**同一套几何**的三种表达；改图前请先读第 5 节。

## 1. 设计说明

### 1.1 它是什么

一个**本项目自有的、中性的几何标识**：圆角方框内是字母 **G3**（Gaokun 3）。

全部形状只用了三种几何基元——**圆环、圆弧、矩形**——没有任何一个点来自厂商 logo：

| 元素 | 形状 | 颜色 |
|------|------|------|
| 外框 | 圆角正方形描边（中心线 66..446，圆角 r=78，描边 28） | `#4EC9B0` 青 |
| 字母 G | 圆环（圆心 189,256，r=70，描边 30）在 3 点钟方向开口 ±34°，加一条从圆心到外径的横杠 | `#FFFFFF` 白 |
| 数字 3 | 两段 250° 圆弧（r=35，描边 30，圆心 358,221 / 358,291），在腰部相接 | `#FFFFFF` 白 |

字母与数字同高（均 170 单位）；整个标识外接框 **408×408**，在 512×512 画布中四周各留 52 px 空白。

### 1.2 为什么这样设计（对齐项目红线）

- **无商标风险**【已核实】：不含、也未临摹华为／荣耀／Ubuntu／Qualcomm／Adreno 的任何商标或官方图形；
  G3 是纯几何构造，字面取自设备代号 `gaokun3`，不指向任何厂商。
- **不依赖字体**【已核实】：`logo.svg` 不用 `<text>`，全部是 `<path>` / `<rect>`；
  `make-logo.py` 也完全用解析式画几何，**不读任何字体文件** ⇒ 在 initramfs 这种没字库的环境里也不会变形或出豆腐块。
- **不写中文**：整个标识只有几何图形，不存在字体缺失问题。
- **只用两色**【已核实】：全图非透明像素只有 `#4EC9B0` 与 `#FFFFFF` 两种颜色，无渐变、无阴影（实测见第 4 节）。
- **小尺寸可辨**【已核实】：整图按 2×2 盒式降采样到 256×256 后，圆角外框、G 的开口与横杠、3 的腰部仍清晰可辨
  （对照图见 `_qa\preview-sheet.png`）。

### 1.3 尺寸与配色参数

| 项 | 值 |
|----|----|
| 交付位图 | 512×512 px，8 bit/通道 RGBA（颜色类型 6），**非隔行** |
| 背景 | **完全透明**（`alpha=0`），只留标识本身 |
| 外框色 | `#4EC9B0`（青） |
| 标识色 | `#FFFFFF`（白） |
| 设计画布 | 512×512 设计单位；`--size` 只改输出分辨率，不改比例 |

## 2. 生成命令

**依赖：零。** 只需要 Python 标准库（`zlib` + `struct` + `math`），不需要 pip、不需要任何图像库。

```bash
# 在构建 VM（Debian 12，python3 3.11）上，进入本目录后：
python3 make-logo.py
```

默认行为：输出 `logo.png`（512×512 RGBA）与两个旋转版，并**立即自检**（读回 PNG 头 + 校验 CRC + 解压 IDAT + 统计像素）。

可选参数（脚本顶部常量与这些开关共同决定几何与配色）：

```bash
python3 make-logo.py --help
python3 make-logo.py --size 256                 # 换输出分辨率
python3 make-logo.py --ss 8                     # 超采样 8×8 = 64 样本/像素（默认 4×4 = 16）
python3 make-logo.py --accent 4EC9B0 --mark FFFFFF   # 换两色
python3 make-logo.py --outdir /tmp/out          # 换输出目录
python3 make-logo.py --no-rotate                # 不生成旋转版
```

转 90°／270° 版本是**脚本同一次运行顺手输出**的，不是外部工具转的：

```bash
# 等价于（脚本内部实现，纯整数像素搬运，无插值、无质量损失）
# logo-rot90.png  = logo.png 顺时针旋转 90°
# logo-rot270.png = logo.png 顺时针旋转 270°
```

### 3.1 ★ 可复现性注意（重要）

脚本对给定参数是**确定性**的，但 **PNG 的压缩字节依赖 zlib 实现**，因此**换一个 zlib 会得到不同的 sha256、
但完全相同的像素**。实测对照【已核实】：

| 生成环境 | `logo.png` 字节数 | sha256 | 像素 |
|---|---:|---|---|
| Debian 12 / python3 3.11.2 / zlib 1.2.13（**本目录交付值**） | 7,445 | `26ee885d…d9f217` | 基准 |
| Windows / python 3.14.7 / zlib-ng 1.3.1 | 6,857 | `94bc8cb7…aab36620` | **逐像素完全相同** |

⇒ 校验交付物时请以**上表的 VM 值**为准；若你在别的机器重跑得到不同 sha256，
先用 `_qa\verify-vm.py` 那类逐像素比对确认图片本身没变，再决定是否替换。

## 4. 自检结果

生成脚本每次运行都会自己做一遍完整自检（读回文件，不是打印内存里的值）。

### 4.1 PNG 容器与解码【已核实】

```text
logo.png        512x512 RGBA depth=8 interlace=0      7445 bytes
logo-rot90.png  512x512 RGBA depth=8 interlace=0      7939 bytes
logo-rot270.png 512x512 RGBA depth=8 interlace=0      8001 bytes
self-check : header, CRC32, IDAT inflate and unfilter all OK
```

自检内容：PNG 签名 → `IHDR` 尺寸/位深/颜色类型 → 每个 chunk 的 CRC32 → `IDAT` 解压 →
逐行反滤波（支持 0–4 全部 filter 类型）→ 像素统计。任一步不符即报错退出（非 0）。

### 4.2 像素统计（三个文件一致）【已核实】

| 指标 | 值 |
|------|----|
| 总像素 | 262,144（512×512） |
| `alpha > 0` 的前景像素 | **61,568（23.49%）** |
| 完全不透明像素（`alpha = 255`） | 59,384（22.65%） |
| 抗锯齿过渡像素 | 2,184（0.83%） |
| 非透明像素的包围盒 | x 52..459、y 52..459（408×408，居中） |
| 出现的颜色数 | **2**：`#4EC9B0`（39,256 px）、`#FFFFFF`（22,312 px） |

### 4.3 交叉验证【已核实】

| 验证 | 方法 | 结果 |
|------|------|------|
| `logo.svg` 与 `logo.png` 是同一套几何 | `python3 _qa/svg-check.py`：用 **SVG 1.1 规范 F.6.5 的端点参数化**独立解析 SVG 里的圆弧（与 `make-logo.py` 的解析式是两条完全不同的代码路径），重新光栅化后与 PNG **逐像素**比对 | 262,144 px 中 **4 px** 不同，且**只差 1 个子样本的 alpha（≤16/255）**，全部落在圆弧平切口的浮点临界线上 ⇒ 几何一致；SVG 反解出的弧参数与设计值精确吻合（G 弧：圆心 (189,256)、r=70、±34°；3 的两段弧：r=35、各 250°） |
| 旋转版正确 | `_qa/verify-vm.py`：用**另一套下标数学**重算 90°/270° 旋转并逐像素比对；再验证「连转 4 次 90° 回到原图」 | 全部 OK |
| 生成脚本可跨机器复现 | VM 与本机分别运行，比对脚本 sha256 与输出像素 | 脚本字节相同、**输出像素完全相同**（容器字节不同，原因见 3.1） |

### 4.4 用了什么工具链

| 环节 | 工具 |
|------|------|
| 生成位图 | **Debian 12（VMware 构建 VM）+ python3 3.11.2 + 纯标准库**（`zlib`/`struct`/`math`/`hashlib`） |
| 上传/取回 | `%TEMP%\vm-scp.ps1` / `vm-scp-get.ps1`；远程执行 `%TEMP%\vm-ssh.ps1` |

## 5. 怎么换图

### 5.1 只换位图（最简单，推荐）

Plymouth 主题只认一个 PNG 文件，**替换 `logo.png` 即可**，其它什么都不用动：

```bash
# 保持 512×512、RGBA（颜色类型 6）最好；Plymouth 会自己缩放到屏幕比例。
cp 你的新图.png /usr/share/plymouth/themes/<主题名>/logo.png
```

新图要求（否则可能显示异常）：

- 格式 **PNG**，**带 alpha 通道**（颜色类型 6，8 bit/通道）；
- 正方形、边长 2 的幂最省事（512×512 或 256×256）；
- **背景透明**（深色启动背景上才不会有难看的方块）；
- 图形四周留一圈空白（本图留了 52/512 ≈ 10%），否则贴边会显得局促。

换完自检一行就够：

```bash
python3 - <<'PY'
import struct
d = open('logo.png','rb').read()
print('sig ok' if d[:8] == b'\x89PNG\r\n\x1a\n' else 'BAD SIGNATURE')
print(struct.unpack('>IIBB', d[16:26]))   # -> (512, 512, 8, 6)
PY
```

### 5.2 换颜色 / 换输出尺寸（用本脚本）

```bash
python3 make-logo.py --accent FF8A3D --mark FFFFFF --size 256 --outdir ./out
```

### 5.3 换几何（改设计）

两处要一起改，保持同步：

1. `make-logo.py` 顶部的常量块（`FRAME_*`、`G_*`、`T3_*`、两个默认色）——这是位图的**唯一真值来源**；
2. `logo.svg` 里的 `<rect>` / `<path>`（`logo.svg` 顶部的注释逐条写明了对应关系，数值一一对应）。

改完跑 `python3 make-logo.py` 重新出图，再跑 `python3 _qa/svg-check.py` 确认两者仍然一致。

### 5.4 方向问题（竖屏面板）

本机内屏原生是 **1600×2560 竖屏**，启动阶段 `fbcon=rotate:1` 也说明过方向问题。
如果 Plymouth 显示的 LOGO 方向不对，直接换用旋转版，**不要**去改几何：

| 现象 | 用哪个文件 |
|------|-----------|
| 方向正确 | `logo.png` |
| 需要整体顺时针转 90° | `logo-rot90.png` |
| 需要整体顺时针转 270°（= 逆时针 90°） | `logo-rot270.png` |

旋转版是**纯像素搬运**（无插值），所以和原图一样清晰。

## 6. 「深色背景上是否清晰」自评

**结论：清晰，且余量很大**【已核实】。依据如下。

### 6.1 对比度（WCAG 2.1 相对亮度公式）

| 前景 | 背景 | 对比度 | 判定 |
|------|------|-------:|------|
| `#FFFFFF` 标识 | `#1A1A1A`（建议的启动底色） | **17.40 : 1** | 远超 AA（4.5:1）与 AAA（7:1） |
| `#4EC9B0` 外框 | `#1A1A1A` | **8.54 : 1** | 超过 AAA（7:1） |
| `#FFFFFF` 标识 | `#000000` | **21.00 : 1** | 满分 |
| `#4EC9B0` 外框 | `#000000` | **10.31 : 1** | 远超 AAA |

即使把外框单独拿出来看（8.54:1），也远高于大字号文本的 3:1 门槛，所以**在 #1A1A1A / #000 上都读得清**。

### 6.2 形状层面的清晰度

- **笔画够粗**：512 px 下最细笔画 28 px；缩到 **256 px 仍有 14 px**，远大于抗锯齿过渡带（1 px），不会糊成一团。
- **面积占比合理**：前景占 23.49%，既不过密（不会变成一坨白块），也不过稀（不会在暗背景上"消失"）。
- **留白充足**：标识距画布边缘 52 px（10%），中心与外框之间水平留 24 px、垂直留 91 px，视觉不挤。
- **抗锯齿**：4×4 超采样（16 样本/像素）后降采样，全图有 2,184 个过渡像素、16 级 alpha 台阶；
  512 px 原尺寸下边缘平滑。需要更细腻可 `--ss 8`（64 级台阶，实测过渡像素 2,546）。
- **纯色无渐变**：只有 2 种颜色，不依赖色彩层次表达信息 ⇒ 即使屏幕色偏、亮度低，形状依然成立。

### 6.3 已知的、有意保留的限制

- 不做多分辨率图标集（只交付 512×512 母版 + 两个旋转版）；Plymouth 需要缩放时由它自己插值。
- 标识只有横向一种排版；旋转版是**整图旋转**，不是"重新排版成竖版"。
- 未提供单色/黑白描边版：本图本来就只有两色，去掉青色也仍可辨认（白色 G3 自带外框内的对比）。
