# 补丁序列

本目录是**面向内核树的一组组补丁**。每个子目录是一个"序列"，目录内固定三件东西：

| 文件 | 作用 |
|---|---|
| `README.md` | 治理元数据（用途 / 基线 / 上游状态 / 是否用于当前发布内核 / 验证 / 回滚）+ 实测依据 |
| `series` | quilt 风格清单：本目录补丁的**应用顺序**（每行一个文件名，`#` 为注释，文件内顺序敏感） |
| `*.patch` | `git format-patch` 产出、带 `Signed-off-by` 的补丁 |

## 三条硬规则

1. **补丁只增不改。** 入库的补丁文件对应一次已发布的内核构建，**不得修改内容**；要有变化就新增编号。
2. **顺序敏感，必须走 `series`。** 同一序列内可能有依赖（例如 `el2-v7.2` 中 `0006` 引入的枚举被 `0010`/`0016` 使用）。
3. **历史归档 ≠ 可用。** `el2-v7.2/`、`iris-el2/` 记录的是**已放弃的技术路线**（EL2 + IRIS），保留是为了可追溯；**当前发布内核不使用它们**。

## 校验

```sh
scripts/check-patches.sh        # series 与 .patch 一一对应、补丁非空且是补丁格式
make patches                    # 同上（CI 的 patches job 也调用它）
```

`--dry-run` 级别的真实应用验证需要内核树，只能在构建宿主上做，方法见各序列 README 的「验证」一节。
