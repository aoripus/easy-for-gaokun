# easy-for-gaokun v0.1.0

发布日期：2026-09-13
适用设备：HUAWEI MateBook E Go 2022 性能版（GK-W76 / GK-W7X-PCB / SC8280XP / gaokun3）

首个源码里程碑：设备鉴别、双系统安装、触屏修复、音频调优、外设调查与内核构建配方落地。

---

## 主要内容

### 设备鉴别与前检

- **变体鉴别前检**（`e28c3b7`）：`scripts/00-preflight.sh` 校验设备树 `compatible`、大核最高频率（目标机为 `2995200` kHz）、面板与触控设备，用于排除 2022 LTE 版（8cx Gen 2 / `gaokun2`）与 2023 降频版。只读脚本，不修改系统状态。
- 型号字符串不是可靠判据：本机 `/sys/class/dmi/id/product_name` 为 `GK-W7X`，而 `/proc/device-tree/model` 不含型号代号，因此前检以设备树与频率为准。

### 触屏

- **根因**（`f73c184`、`2b02206`）：Himax HX83121A 的上报接口由 TLMM `gpio174` 选择。引导固件将其留在高电平，IC 处于 I²C-HID 模式，而内核通过 SPI 驱动它，因此永远收不到触摸数据；中断配置为 `IRQ_TYPE_LEVEL_LOW`，实测开机至今仅触发 1 次，且 SPI 寄存器访问与固件重载均不报错。
- **修复**：在 `ts0_default` 中把 `gpio174` 描述为低电平输出，并保证在触控固件重载前生效，补丁见 `patches/0001-*`。脚本在 `dd` 之前将其编译进 ESP 上的 DTB，首次启动即可用，无需常驻进程。
- **实机对照**：该 IRQ 计数由 1 变为持续增长（实测 13455 → 27199），`/dev/input/event11` 正常上报触摸。

### 音频

- **gaokun3 专用 UCM2 profile**（`5d21054`）：以 `${CardLongName}.conf` 形式装入 `conf.d/sc8280xp/`，优先于镜像自带的 DMI 分发器，且不会被 `alsa-ucm-conf` 升级覆盖。`BootSequence` 把 `SpkrLeft/Right PA Volume` 由 X13s profile 的 `12`（−3.00 dB）提升到内核上限 `17`（0.00 dB）。
- **执行顺序修正**（`cfaaa90`）：`30-audio.sh` 改为「重启音频栈 → 写增益 → `alsactl store`」。此前先写增益再重启，codec idle reset 会把控件复位为驱动默认值。
- 文档记录了三层归因（内核限幅、缺少逐机型调音、加载双扬声器 profile）与量化结果：当前链路距硬件可达的 +18.00 dB 尚余 21.00 dB，在取得主动扬声器保护与校准数据之前不作调整（`4caed71`、`8a1b22f`）。

### 视频硬解

- **归因**（`8507202`）：本机视频单元是 Qualcomm IRIS (Gen1)，不是 Venus AR50。基线内核的 venus 节点没有 `video-firmware` 子节点，`venus_firmware_init()` 因此设 `core->use_tz = true` 走 PAS 安全世界路径并被拒绝（`-EINVAL`）；驱动把任何失败统一改写为 `error -22 initializing firmware`，该报错不表示固件文件损坏。
- **构建配方与前置工具**（`4717fd4`、`fb306e9`）：`tools/gaokun-iris-dts-prep.py` 在 v7.2-rc2 树上补齐 `iris` / `videocc` 节点与板级 `firmware-name`，配方见 `docs/build-kernel-iris.md`。
- 上游 `sc8280xp.dtsi` 自 v7.3-rc1 起才有视频节点（`3a52eef16b97`、`595eb4144f2e`），v7.1-rc3 与 v7.2-rc2 均无。

### 指纹

- **结论**（`ddaed56`、`160256e`、`343e6f6`）：本机指纹为 FocalTech FTE7001（`ACPI\FTE7001`），其 SPI 由 Qualcomm 安全世界独占，非安全侧只获得一个 GPIO 中断连接，取图与比对在签名 trustlet `fingerpr.mbn` 内完成。Linux 侧无法通过常规内核驱动路线使用，原因不是缺少驱动实现，而是非安全世界拿不到该总线。
- **三条独立证据**：`Enum\ACPI` 下 `FTE7001` 枚举 1 次且 `GDIX5125` / `ELAN7001` / `GXFP5130` 均为 0；FTE7001 的连接描述符为 `01 02`（GPIO_INT）而非 `02 02`（SPI），而同机已知 SPI 的 `HIMX0002` 为 `02 02`、已知 UART 的 `QCOM066B` 为 `02 03`；trustlet 内含 `focal_fp_spi.c` 与 `qsee_spi_open` / `full_duplex`，I²C 字符串为 0 条。
- **方法论修正**：`Drv/` 目录不是本机硬件清单，而是整份 Gaokun 家族主镜像的驱动库（`PAR_install.cmd` 以 `DISM /add-driver /recurse` 注入 FocalTech 与 Goodix 两套指纹驱动），判断本机硬件必须依据运行时枚举结果。

### 双系统安装

- **分区级 dd**（`8b04d0e`、`48f608c`）：镜像为整盘镜像（GPT + 1 GiB FAT32 ESP + ~11 GiB ext4 rootfs），不可整体 `dd` 进单个分区。`dd` 保留文件系统 UUID，因此 `/etc/fstab` 与 BLS 的 `root=UUID=` 无需改动。
- 脚本包含 GPT 备份、UUID 逐字校验、`resize2fs` 撑满、`loader.conf` 修复与 ESP 上的 DTB 预编译。

### 工具

- `tools/win-acpi-hive.py`（`ddaed56`）：离线解析 Windows `SYSTEM` hive，读出本机实际枚举过的 ACPI 设备与资源分配。
- `tools/acpi-devmem-dump.py`（`67d4ce2`）：从 `/dev/mem` 读 ACPI 表。arm64 上该路径受 `CONFIG_STRICT_DEVMEM` 限制，工具头部记录了实测结论。
- `tools/gaokun-iris-dts-prep.py`（`fb306e9`）：为 v7.2-rc2 树前置 IRIS 设备树节点。

## 已知问题

- 视频硬解尚未跑通：IRIS 与 Venus 使用同一套 PAS 调用序列（`qcom_scm_pas_auth_and_reset`、`qcom_scm_mem_protect_video_var`），而本机 `qcom_scm_pas_init_image()` 已知失败，更换 media 驱动不改变该通路是否可用。
- 手写笔通道未实现：Linux 侧驱动不声明 `BTN_TOOL_PEN` / `ABS_PRESSURE`。
- `qcom-apm` 开机报 `CMD timeout`（声卡仍能注册）；`qcom-soundwire` 端口数告警经代码核对属良性。
- RTC 开机时间错误，依赖 NTP 纠正。
- 镜像自带缺陷：`loader.conf` 的 `default` 指向会卡住的非 `el2` 条目；根目录属主为 uid 1001。安装脚本会处理，详见 `README.md` §2 与 `docs/install-dualboot.md`。
- 本机没有 EDL / 9008 救援通道，引导损坏无法用刷机工具恢复。
