# ADR-0006：诊断内核与发布内核分离

- **状态**：已接受
- **日期**：2026-09-13
- **相关**：[`docs/touch-idle-policy.md`](../touch-idle-policy.md)、[`docs/releasing.md`](../releasing.md)

## 背景（Context）

排查触屏空闲行为时，需要一些"能直接看内部状态"的手段：不依赖中断地读一帧并返回校验和、
显式屏蔽/恢复中断、裸 AHB 读写寄存器、给 IC 发任意 AFE 命令。这些手段在排查中起了决定作用
——例如正是"屏蔽中断后帧数据仍在变化"这一观察，推翻了此前"AFE 命令让 IC 停流"的误判。

但同一些手段在**正常使用**时是负担甚至风险：裸寄存器写入可能把触屏弄死，
无条件的 AFE 命令会改变芯片状态，额外的 sysfs 节点扩大攻击面，也让"发布产物"难以审计。
同时，本项目曾因为**测量工具本身改变了被测对象**（写 sysfs 会屏蔽中断）而连续两轮得出错误结论。

## 决策（Decision）

- 诊断能力与发布产物**分离**：
  - 诊断内核（`r3-dev` 之类，**不发布**）才带全部取证节点与开关。
  - 发布内核**默认关闭**这些节点：`regs`（裸 AHB 读写）受 `allow_raw_ahb` 门控、默认关；
    AFE 相关开关（`afe_skip_trigger`、`afe_skip_readback`、`afe_log_response`）默认关。
  - 允许保留**只读**观测节点：`idle_state`（空闲策略状态）与参数 `idle_enter_frames`/`idle_poll_ms`，
    因为它们既是运维入口，也是"为什么没进空闲"的唯一可信判据。
- 任何"现象消失"的结论，**必须先证明操作本身只做了它声称的事**；
  测量工具本身要被怀疑，不能拿它当基准。
- 内核差异以可审阅补丁形式入仓（[`patches/`](../../patches/README.md)），
  Release 资产另带一枚合并补丁，便于外部审计与复现。

## 后果（Consequences）

- **正面**：发布产物的行为面更小、更好审计；诊断需求仍可满足（本地构建诊断内核，
  或用 `scripts/gk-install-kernel.sh` 装一份不发布的诊断条目）。
- **负面 / 代价**：排查时必须显式构建/装载诊断内核，多一道流程；
  发布内核的某些问题在本地不可直接复现，需要再造一次诊断构建。
- **风险**：诊断开关若被误留为默认开启，会把"调试构建"混进发布产物 ——
  因此发布门禁里包含对默认配置的检查（见 [`docs/releasing.md`](../docs/releasing.md)）。

## 替代方案与放弃原因（Alternatives）

| 方案 | 为什么没采用 |
|---|---|
| 全部节点都进发布内核，靠文档提醒别用 | 裸寄存器写与 AFE 命令的风险不应留给"使用者自觉" |
| 干脆不保留任何观测节点 | 没有 `idle_state` 就只能靠 IRQ 速率反推，而"为什么没进空闲"无法观测（实机吃过这个亏） |
| 诊断代码只留在本地、不入仓 | 结论无法复核；本项目要求"结论可追溯、可复现" |

## 回滚（Rollback）

诊断节点本身不改变默认行为（默认关闭/只读）；如需彻底移除，切回不带诊断增量的内核条目即可。
